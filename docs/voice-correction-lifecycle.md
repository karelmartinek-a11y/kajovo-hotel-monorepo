# SmartPlan voice correction lifecycle

The host keeps authorization distinct from transport evidence. A receipt preserves the original owner, logical call, voice session, exact proposal/fingerprint, native input and expiry. A fresh exact prepare under a new native intent appends a separate authorization; it does not rewrite the original receipt or previous grant.

The additive dagmar_smartplan_authorizations table records independent confirm_transport and commit_transport. New grants start not_sent. The host reserves a grant before queue admission, then marks maybe_sent immediately before the authenticated HTTP emission, after current generation, client/session, metadata and model ACK guards. A network exception after that boundary remains uncertain. Initialization, queue rejection and the last guard cannot create sent evidence. CancelledError follows the same durable classification. A proven cancelled_not_sent grant cannot be recovered into its first effect. Legacy /host/confirm approval is separate; it cannot establish business commit emission.

Legacy rows without transport evidence remain unknown. No migration backfills consent or dispatch. A declared owner-scoped GET proposal status may return the original stored applied result; prepared, absence, expired approval and a 404 never prove never_sent or authorize commit. Current authorized sent/maybe-sent attempts recover only the original proposal ID. Definitive public nested SmartPlan errors with effect_state none and a recognized pre-effect phase close the grant; prepared/applied/uncertain evidence never invents a new first-effect authorization. Delivery journals preserve original request_key and distinguish reservation from emission for prepare/bind/observe.

SmartPlan has one cancellable capability lifecycle. Each initialize attempt has the existing 35-second total budget. Transient failures use exponential delay from 0.5 seconds capped at 15 seconds, with 20 percent jitter; one lifecycle owns one attempt at a time. Authentication, unsupported profile, credential echo and integrity failures stay closed until repaired. A failed provider update or its cleanup does not kill transient recovery. The failed transport is closed only by this capability lifecycle.

Terminal SDK transport loss synchronously clears metadata, projection and scoped ACK, wakes the host immediately and prevents call_tool from reconnecting a host-managed client under an old ACK. A new SDK transport has a new backend transport_session_id. The provider ACK/cache binds the exact metadata/projection plus current client and transport session. Even an unchanged digest after invalidation requires a public wire recheck and projection; old ACKs and late ACKs cannot reactivate it. Ordinary speech, Home Assistant and durable original recovery identities remain independent.

Known public fixtures include current HA2.1.25/ecdd and candidate HA2.1.26/2da13, current SmartPlan1.6.8/v2/f9ad and candidate1.6.9/v3/1ab2, plus pinned older2025 legacy compatibility paths. Unknown breaking input/output revisions remain closed. HA reading selectors are exact typed row+rNN pairs. The compact complete path counts typed targets and preserves their row/revision, source, availability, value and original observed_at in one model-visible successful output, with no automatic second read.

Schema marker1 and nullable added Delivery columns remain readable by the prior reader. PostgreSQL timestamp ALTER uses the dialect's DateTime type; the PG gate rehearses upgrading an existing v99 table and proves original IDs/states unchanged and legacy evidence null. This is data compatibility, not permission to roll the voice runtime back to v99, which lacks v3 support and these lifecycle fixes. Service rollback to old tested public fixtures can keep this bridge. A voice-only corrective release must retain authorization, metadata, projection and ACK fences through main/CI/standard deploy, without restoring an old database.

Paid Realtime, acoustic/audio and physical device evidence are separate from source/store/SDK/host ACK fixtures. Required release gates and copyout installs remain unchanged.
