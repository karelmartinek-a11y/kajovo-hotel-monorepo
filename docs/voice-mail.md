# Hotel voice mail

The hotel API owns an independent MAIL MCP client and 20 backend-managed functions alongside assistant_memory and smart_technologie. Portable Voice Core remains tool-free. Only authenticated active admin sessions can operate mail; ownership is rechecked before each operation and mail status HTTP is session-scoped.

The only transport is `https://apimail.hcasc.cz/mcp`, A-only DNS, HTTPS bearer authentication, no redirects/private fallback. `KAJOVO_MAIL_MCP_URL` must equal that canonical URL; `KAJOVO_MAIL_MCP_TOKEN` stays in the backend environment. Compose passes both; the existing SSH release mechanism preserves all existing environment values with umask 077 and permissions 0600. Never expose values in source, browser, model, logs or reports. HA and MAIL remain independent services. Mailbox credentials belong exclusively to MAIL MCP; the hotel has only its MCP bearer credential.

`packages/dagmar-server/src/dagmar_server/mail_mcp_catalog.json` is the installed `mail-mcp/1` tools/list contract. Initialization checks all tool names and input/output schemas; mismatch disables only mail. Every request/result is schema-validated. Model schemas omit confirmation_token, explicit_user_bypass and idempotency_key; backend injects private values. SDK errors are reduced to fixed categories, never payload text. Degraded account/index state is public metadata and must be announced as incomplete search. Mail failure never blocks general conversation, memory retrieval or HA.

Message previews are summaries with attachment metadata. Body chunks and completion flags retain the exact MCP contract. Reading does not mark read. Opaque references must first have appeared in this session's mail results. Draft operations preserve versions, allowed sender accounts, reply/reply_all and real Drafts; deletes use Trash. V1 attachment edit/send limitations remain server authoritative.

Voice-created drafts use deterministic escaped HTML from the authoritative text. Existing text-only drafts are accepted. Independent HTML is rejected with UNSUPPORTED_CAPABILITY before prepare/bypass; it is never silently rewritten or discarded. Envelope-only edits cannot erase it. An explicit text edit creates the safe projection. Both the hotel adapter and Mail MCP authenticated voice-backend client enforce this policy, including confirmed-send validation. The 20 tool schemas remain mail-mcp/1.

Standard sending retrieves the current draft, checks its version and prepares an immutable five-minute candidate. Backend validates the complete envelope and the exact installation body hash, then authors a readback in cs/en/de/sk. Maximum readback is 4500 characters including envelope and question; oversized drafts are rejected before preparing. Candidate token is AES-256-GCM encrypted using the voice master key with a separate mail AAD bound to operation identity. Only metadata and encrypted tokens are persisted; bodies and readback text stay transient.

Consent requires matching completed provider audio for the entire backend script, matching started and drained playback, and the next genuine audio input with an unambiguous yes. Text, model arguments, mail contents, earlier speech and interrupted readbacks cannot authorize sending. The receipt is transactionally reserved once. Mail and registry confirmations do not overlap; bypass speech during either dialog is not consent. Foreign playback starts, concurrent responses and any global buffer clear invalidate the mail readback. Terminal mail dialog generation is suppressed when normal VAD already generates the response, preventing duplicate provider generation and call shutdown. A stop without a matched start cannot arm consent. Completion/drain order is tolerated, but an unrelated response ID never authorizes sending. The admin panel exposes envelope/body read-only during a valid candidate, never a send button. Changed/expired/interrupted drafts require fresh prepare. Unused confirmations cannot be restored after a process restart because no spoken-content proof is recreated.

Explicit bypass requires current genuine human audio saying `Odešli bez potvrzení` (or the fixed English/German/Slovak equivalent; Czech ASR may spell the acoustically identical imperative as `Odešly bez potvrzení`), tied to a draft already selected by mail_draft_get/create/update, its version and content hash. The proof expires after 30 seconds and is consumed. Before sending, backend reloads and compares the draft. New human audio or proof expiry during that reload prevents the unsent bypass from being reserved. No model boolean authorizes bypass.

Mutation identity is persisted before MCP using owner/session/call/tool and argument digest. Pending/uncertain identical operations reuse the original key even after restart. Confirmed sends recover only the original candidate/private token. Uncertain sends block new prepare/bypass identities; the same draft is also blocked across later authenticated sessions. `SMTP_OUTCOME_UNKNOWN` never becomes a fresh send. Success retains receipt metadata; SMTP accepted is not recipient delivery and rejected recipients/Sent-copy status must be announced.

Mail content remains untrusted provider/tool data. Automatic curation receives only bounded, completed genuine human audio turns. A mail-derived or ambiguously mixed batch is skipped with a safe metadata reason; it does not disable memory writes for the rest of the call. A new explicit genuine user instruction can remember a fact or note after mail, including a deliberately requested mail fact. Quoted instructions or confirmations in mail/tool content cannot create human intent or consent. The approved pinned Dagmar profile cannot be changed by mail/curation. Ordinary logs retain only metadata; explicit debug may capture structurally redacted content and separate encrypted audio under the diagnostic policy.

Validation: contract and security pytest, existing Voice Core/registry regressions, responsive real HTTP/auth/DB mail panel (provider media isolated), full `pnpm ci:gates` and actual API image. Live acceptance must separately verify the public MCP from the runtime, owner/RBAC/status and provider voice. Readiness is evaluated from current account results, not a historical missing-password assumption. Healthy authentication, unavailable connections and incomplete indexing are distinct. Page sizes are not mailbox/unread totals. A real SMTP acceptance test always needs separate explicit consent and recipient.

The opt-in paid `playwright.voice-mail-live.config.ts` test plays the WAV at `VOICE_CORE_AUDIO_FIXTURE` through a real WebRTC audio track after sideband readiness. It keeps silence flowing for VAD and captures only the mail panel at desktop/tablet/phone sizes. Ordinary provider responses may contain `metadata: null`; outside an active readback they leave mail consent unchanged and never crash the sideband. During reading/awaiting confirmation a competing response invalidates the candidate.

Mail read diagnostics: provider-acknowledged `voice.host.mail_delivery` includes `mail_diagnostic` with call digest, separate index/connection booleans, complete, page size/counts and next-page boolean. No content, refs, cursor, arguments, addresses or transcript. Page counts are not unread totals; diagnostics do not change model behavior. See docs/voice-mail-diagnostic-impact-matrix.md.

Connection recovery: one call-owned manager closes the old SDK session before reconnecting. Each outage has at most five attempts with 1/2/4/8-second backoff and a 30-second initialization deadline. Authentication/schema mismatch is terminal for that call; cancellation stops attempts. A failed safe read may replay once with the same arguments after fresh authentication, within a 45-second wait. Writes and SMTP are never automatically replayed. Original uncertain identities remain in the durable journal.

Rollback: retain the Mail MCP pre-release source/dist backup and current mutation ledger; restore code only, not a stale send database. Hotel rollback is a main revert through exact-SHA CI and standard deploy. Paid write acceptance uses an isolated backend, test mailbox and non-delivering SMTP stub; actual production provider acceptance is read-only. Real SMTP acceptance, Sent copy and recipient delivery require separate explicit recipient/consent. See voice-mail-remediation-impact-matrix.md.

Isolated paid write harness: build the installation package, start tests/live-mail-server.js with VOICE_CORE_LIVE_SMOKE=1 (loopback ports 8795/8796), then tests/voice_mail_live_host.py with the provider key delivered on stdin (loopback 8794). This test module injects the SDK transport only inside the isolated process and verifies all 20 production schemas; it cannot load mailbox secrets or connect a real IMAP/SMTP gateway. Run playwright.voice-mail-isolated-live.config.ts with VOICE_MAIL_SEND_AUDIO, VOICE_MAIL_YES_AUDIO and VOICE_MAIL_BYPASS_AUDIO temporary WAV paths. Use synthetic instructions for the fixed selected example.invalid draft, then remove temporary audio. The test proves genuine provider interpretation and backend consent, actual MCP/composer and SMTP-stub acceptance; it does not prove real SMTP delivery or physical microphone/speaker behavior.
