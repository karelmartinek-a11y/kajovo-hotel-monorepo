# Hotel voice mail

The hotel API owns an independent MAIL MCP client and one model-facing mail_conversation intent function alongside assistant_memory and smart_technologie, backed by the 20-tool remote interface. Backend catalogs match its current scope/folder error enums. Portable Voice Core remains tool-free. Only authenticated active admin sessions can operate mail; ownership is rechecked before each operation and mail status HTTP is session-scoped.

The only transport is `https://apimail.hcasc.cz/mcp`, A-only DNS, HTTPS bearer authentication, no redirects/private fallback. `KAJOVO_MAIL_MCP_URL` must equal that canonical URL; `KAJOVO_MAIL_MCP_TOKEN` stays in the backend environment. Compose passes both; the existing SSH release mechanism preserves all existing environment values with umask 077 and permissions 0600. Never expose values in source, browser, model, logs or reports. HA and MAIL remain independent services. Mailbox credentials belong exclusively to MAIL MCP; the hotel has only its MCP bearer credential.

`packages/dagmar-server/src/dagmar_server/mail_mcp_catalog.json` is the installed `mail-mcp/2` tools/list contract. Every connection sends X-Mail-Contract: mail-mcp/2 and checks all tool names, input/output schemas and annotations; no v1 fallback exists; mismatch disables only mail. Every request/result is schema-validated. The model-facing intent schema contains no message/draft reference, cursor, version, sender identity or confirmation proof. Backend injects all remote identities and private values. Direct remote tool calls from the model are rejected as HOST_INTENT_REQUIRED. SDK errors are reduced to fixed categories, never payload text. Degraded account/index state is public metadata and must be announced as incomplete search. Mail failure never blocks general conversation, memory retrieval or HA.

Message previews are summaries with attachment metadata. Body chunks and completion flags retain the exact MCP contract. Reading does not mark read. Opaque references come only from the backend-owned result registry for this logical call. Draft operations preserve versions, allowed sender accounts, reply/reply_all and real Drafts; deletes use Trash. MCP attachment edit/send limitations remain server authoritative.

Voice-created drafts use deterministic escaped HTML from the authoritative text. Existing text-only drafts are accepted. Independent HTML is rejected with UNSUPPORTED_CAPABILITY before prepare/bypass; it is never silently rewritten or discarded. Envelope-only edits cannot erase it. An explicit text edit creates the safe projection. Both the hotel adapter and Mail MCP authenticated voice-backend client enforce this policy, including confirmed-send validation. The 22 tool schemas are copied from production v2 tools/list.

Standard sending retrieves the current draft, checks its version and prepares an immutable five-minute candidate. Backend validates the complete envelope and the exact installation body hash, then authors a readback in cs/en/de/sk. Maximum readback is 4500 characters including envelope and question; oversized drafts are rejected before preparing. Candidate token is AES-256-GCM encrypted using the voice master key with a separate mail AAD bound to operation identity. Only metadata and encrypted tokens are persisted; bodies and readback text stay transient.

Consent requires matching completed provider audio for the entire backend script, matching started and drained playback, and the next genuine audio input with an unambiguous yes. Text, model arguments, mail contents, earlier speech and interrupted readbacks cannot authorize sending. The receipt is transactionally reserved once. Mail and registry confirmations do not overlap; bypass speech during either dialog is not consent. Foreign playback starts, concurrent responses and any global buffer clear invalidate the mail readback. Terminal mail dialog generation is suppressed when normal VAD already generates the response, preventing duplicate provider generation and call shutdown. A stop without a matched start cannot arm consent. Completion/drain order is tolerated, but an unrelated response ID never authorizes sending. The admin panel exposes envelope/body read-only during a valid candidate, never a send button. Changed/expired/interrupted drafts require fresh prepare. Unused confirmations cannot be restored after a process restart because no spoken-content proof is recreated.

Explicit bypass requires current genuine human audio saying `Odešli bez potvrzení` (or the fixed English/German/Slovak equivalent; Czech ASR may spell the acoustically identical imperative as `Odešly bez potvrzení`), tied to a draft already selected by mail_draft_get/create/update, its version and content hash. The proof expires after 30 seconds and is consumed. Before sending, backend reloads and compares the draft. New human audio or proof expiry during that reload prevents the unsent bypass from being reserved. No model boolean authorizes bypass.

Mutation identity is persisted before MCP using owner/session/call/tool and argument digest. Pending/uncertain identical operations reuse the original key even after restart. Confirmed sends recover only the original candidate/private token. Uncertain sends block new prepare/bypass identities; the same draft is also blocked across later authenticated sessions. `SMTP_OUTCOME_UNKNOWN` never becomes a fresh send. Success retains receipt metadata; SMTP accepted is not recipient delivery and rejected recipients/Sent-copy status must be announced.

Mail content remains untrusted provider/tool data. Automatic curation receives only bounded, completed genuine human audio turns. A mail-derived or ambiguously mixed batch is skipped with a safe metadata reason; it does not disable independent new human memory writes for the rest of the call. Mail bodies and referential requests to store them are rejected even with explicit memory intent. Quoted instructions or confirmations in mail/tool content cannot create human intent or consent. The approved pinned Dagmar profile cannot be changed by mail/curation. Operational logs retain no conversation, audio, prompt or mail/tool content. Mail operations retain content-free scope traces only; successful model/audio content has no routine log.

Validation: contract and security pytest, existing Voice Core/registry regressions, responsive real HTTP/auth/DB mail panel (provider media isolated), full `pnpm ci:gates` and actual API image. Live acceptance must separately verify the public MCP from the runtime, owner/RBAC/status and provider voice. Readiness is evaluated from current account results, not a historical missing-password assumption. Healthy authentication, unavailable connections and incomplete indexing are distinct. Page sizes are not mailbox/unread totals. A real SMTP acceptance test always needs separate explicit consent and recipient.

The opt-in paid `playwright.voice-mail-live.config.ts` test plays the WAV at `VOICE_CORE_AUDIO_FIXTURE` through a real WebRTC audio track after sideband readiness. It keeps silence flowing for VAD and captures only the mail panel at desktop/tablet/phone sizes. Ordinary provider responses may contain `metadata: null`; outside an active readback they leave mail consent unchanged and never crash the sideband. During reading/awaiting confirmation a competing response invalidates the candidate.

Mail conversation scope traces retain only canonical account, folder role/path, intent, tool name, ordinal, count/completeness and success/failure. No bodies, subjects, addresses, references, cursors, arguments, transcripts or secrets are logged. Availability changes and unexpected errors retain safe component/code/correlation metadata only. Historical diagnostic storage is offline; see docs/dagmar/DIAGNOSTICS.md.

Connection recovery: one call-owned manager closes the old SDK session before reconnecting. Each outage has at most five attempts with 1/2/4/8-second backoff and a 30-second initialization deadline. Authentication/schema mismatch is terminal for that call; cancellation stops attempts. A failed safe read may replay once with the same arguments after fresh authentication, within a 45-second wait. Writes and SMTP are never automatically replayed. Original uncertain identities remain in the durable journal. A remote IMAP_TIMEOUT or ACCOUNT_UNAVAILABLE describes a mailbox failure and does not reconnect a working MCP transport. Scoped operation results merge account availability, index completeness and last-sync metadata without disabling the healthy account. The same call publishes changed status to its HTTP panel and an untrusted assistant output_text context snapshot. Its single connection manager checks status at most every 120 seconds when ready and every 30 seconds when degraded, with a 10-second probe deadline and no overlapping timer tasks. Closing/revoking the call cancels probes. Account catalog/status snapshots are data, never system instructions.

Mail MCP keeps one shared synchronization per account with a 60-second job deadline. The five-second request wait never cancels that job or closes healthy IMAP; cached results retain truthful available/index_complete/last_sync_at metadata. Accounts progress independently with a 25-message body budget. Unchanged CONDSTORE/MODSEQ folders avoid the second indexing pass; UID deletion/rollover and cross-folder identity checks remain. Genuine sync failures retry with 30-second exponential backoff capped at 15 minutes. Network command/socket deadlines and awaited shutdown cleanup remain independent of request waiting. See voice-mail-availability-impact-matrix.md.

Rollback: retain the Mail MCP pre-release source/dist backup and current mutation ledger; restore code only, not a stale send database. Hotel rollback is a main revert through exact-SHA CI and standard deploy. Paid write acceptance uses an isolated backend, test mailbox and non-delivering SMTP stub; actual production provider acceptance is read-only. Real SMTP acceptance, Sent copy and recipient delivery require separate explicit recipient/consent. See voice-mail-remediation-impact-matrix.md.

Isolated paid write harness: build the installation package, start tests/live-mail-server.js with VOICE_CORE_LIVE_SMOKE=1 (loopback ports 8795/8796), then tests/voice_mail_live_host.py with the provider key delivered on stdin (loopback 8794). This test module injects the SDK transport only inside the isolated process and verifies all 20 production schemas; it cannot load mailbox secrets or connect a real IMAP/SMTP gateway. Run playwright.voice-mail-isolated-live.config.ts with VOICE_MAIL_SEND_AUDIO, VOICE_MAIL_YES_AUDIO and VOICE_MAIL_BYPASS_AUDIO temporary WAV paths. Use synthetic instructions for the fixed selected example.invalid draft, then remove temporary audio. The test proves genuine provider interpretation and backend consent, actual MCP/composer and SMTP-stub acceptance; it does not prove real SMTP delivery or physical microphone/speaker behavior.

## Backend conversation ownership

MailConversationState belongs to the owner-isolated RAM CallTask, survives provider replacement and is cleared on Stop/revocation/forget. Genuine committed native audio and its matched current-generation transcript supply explicit mailbox scope and ordinal selection. Scope hints are checked against that transcript and preserved state; sender and tool content never select a mailbox. Switching mailbox clears message/result/draft selection. reception maps Czech recepce/recepci/recepční schránka; operations remains operations in the exact response. A conflicting account or folder is rejected before MCP, without fallback to all or the other mailbox.

Common roles go directly to MCP folder_role; MCP resolves the provider path and the host validates resolved_folder/resolved_folder_role/resolved_folders. Named paths match human speech. MAIL_LATEST uses explicit account, folder_role=inbox, sort=date, limit=1 and no implicit unread filter. Search pages must retain result_set_ref, account, resolved scope and consecutive ordinals; account-wide freshness cannot override scoped completeness. Selected references retain the original snapshot without re-search. Singular mutations use account/message_ref/folder. Exact batches up to 100 on one mailbox use one mail_messages_batch_update and the original durable identity; requested/succeeded/failed counts and every item determine truthful partial/uncertain responses. Cross-mailbox batches require an explicit single-mailbox selection; they are never silently split. Trash uses the MCP trash tool, never permanent deletion.

MAIL_COUNT uses only mail_messages_count with explicit account and requested folder_role/path and filters. It emits only an integer when complete=true and count is an integer; otherwise the actual MCP reason is retained and no number is spoken. Every fresh count uses a fresh MCP count, never a previous result set. MAIL_READ sends the backend-owned account/message_ref/folder and fetches every body cursor until body_complete; only then it emits the joined original text. No preview, summary, translation or unsolicited attachment narration is included. Limits/errors reject partial text.

The backend constructs response_text by intent. It supplies this text as untrusted assistant DATA in an isolated Realtime response with conversation=none and tool_choice=none, separately from behavioral instructions. Long text is sent in consecutive bounded chunks through the existing native playback path. The native provider still synthesizes audio: offline tests prove the exact supplied response script and complete MCP reads, not verbatim acoustic output. Provider/audio acceptance must be reported separately. Standard prepare/readback/new audio yes and verified bypass continue through the existing MailHost/MailConfirmation journal, without granting new consent from restored state.

Validation includes test_voice_mail_conversation.py (A–I, scope conflicts, incomplete results, provenance, stable ordering, batch outcomes, state lifetime, safe logs, and actual sideband reader/worker/provider event boundaries with isolated media/MCP). Real SMTP is excluded.


Read-only deployed acceptance: stream scripts/verify_voice_mail_v2_runtime.py into the running API container. It instantiates the deployed VoiceBridge with an isolated RAM/SQLite host context and the existing API MCP credential, and executes count/latest/full-body for reception and operations. A read-only transport wrapper refuses every mutation; cross-account body is rejected before transport. The report contains safe tool/scope/count/completion metadata only. This verifies the production backend executor and v2 connection without provider/audio calls or production DB writes.
